# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

### IProduct - товар

Интерфейс описывает данные одного товара в каталоге

interface IProduct {
id: string;
description: string;
image: string;
title: string;
category: string;
price: number | null;
}

### TPayment — способ оплаты

Тип определяет допустимые способы оплаты:
'card' — банковской картой;
'cash' — наличными.

### IBuyer - покупатель

Интерфейс описывает данные покупателя

interface IBuyer {
payment: TPayment | null;
email: string;
phone: string;
address: string;
}

payment: TPayment | null - способ оплаты
email: string - электронная почта
phone: string - номер телефона
address: string - адрес доставки

### IBuyerErrors - ошибки валидации

Тип описывает сообщения об ошибках для полей покупателя.

type IBuyerErrors = Partial<Record<keyof IBuyer, string>>;

Использует ключи IBuyer. Каждое поле необязательно и содержит строку с текстом ошибки

### IProductsResponse - ответ сервера с каталогом

Интерфейс описывает данные, получаемые от сервера при запросе каталога товаров

interface IProductsResponse {
total: number;
items: IProduct[];
}

Поля:
total: number - общее количество товаров
items: IProduct[] - массив товаров, каждый из которых соответствует интерфейсу IProduct

### IOrder — данные заказа

Интерфейс описывает объект, который отправляется на сервер при оформлении заказа

interface IOrder extends IBuyer {
payment: TPayment;
total: number;
items: string[];
}

Наследует поля интерфейса IBuyer:
payment: TPayment — способ оплаты
email: string — электронная почта покупателя
phone: string — телефон покупателя
address: string — адрес доставки

Дополнительные поля:
total: number — общая стоимость заказа
items: string[] — массив идентификаторов заказанных товаров

### IOrderResponse - ответ сервера на заказ

Интерфейс описывает ответ сервера после успешного оформления заказа

interface IOrderResponse {
id: string;
total: number;
}

Поля:
id: string - идентификатор оформленного заказа
total: number - итоговая сумма заказа, подтверждённая сервером

## Модели данных

### Products - каталог товаров

Класс отвечает за хранение каталога товаров
и выбранного товара

constructor(events: IEvents)

Поля:
items: IProduct[] - массив всех товаров
selectedItem: IProduct | null - выбранный товар
`events: IEvents` - брокер событий, переданный через конструктор

Методы:
setItems(items: IProduct[]): void - сохранить товары
getItems(): IProduct[] - получить все товары
getItem(id: string): IProduct | undefined - найти товар по ID
setSelectedItem(item: IProduct): void - выбрать товар
getSelectedItem(): IProduct | null - получить выбранный товар

### Buyer - данные покупателя

Класс отвечает за хранение и проверку
данных покупателя при оформлении заказа

constructor(events: IEvents)

Поле:
data: IBuyer - полный объект данных покупателя
`events: IEvents` - брокер событий, переданный через конструктор

Методы:
setData(data: Partial<IBuyer>): void - обновить переданные поля, сохранив остальные
getData(): IBuyer - получить полный объект данных покупателя
clear(): void - восстановить начальные значения всех поле
validate(): IBuyerErrors - проверить заполнение полей и вернуть ошибки

### Basket - корзина товаров

Класс отвечает за хранение товаров,
которые покупатель добавил в корзину

constructor(events: IEvents)

Поле:
items: IProduct[] - массив товаров в корзине
`events: IEvents` - брокер событий, переданный через конструктор

Методы:
getItems(): IProduct[] - получить товары
addItem(item: IProduct): void - добавить товар
removeItem(item: IProduct): void - удалить товар
clear(): void - очистить корзину
getTotal(): number - получить общую стоимость
getCount(): number - получить количество товаров
hasItem(id: string): boolean - проверить наличие товара

## Слой коммуникации

### LarekApi - работа с сервером

Класс отвечает за получение каталога товаров
с сервера и отправку оформленных заказов.

Для выполнения запросов использует готовый
класс Api через интерфейс IApi

Конструктор:

constructor(api: IApi) — принимает объект для работы с API

Поля:

api: IApi — объект для выполнения запросов

Методы:

getProducts(): Promise<IProductsResponse> - выполняет GET-запрос на /product/ и возвращает данные каталога товаров.

postOrder(data: IOrder): Promise<IOrderResponse> - выполняет POST-запрос на /order/ и возвращает подтверждение оформленного заказа

## Слой представления (View)

Слой представления отвечает за отображение данных в интерфейсе приложения и обработку действий пользователя

Все классы представления наследуются от базового класса `Component`
Данные для отображения поступают через метод `render()` и сеттеры

### Header — шапка сайта

Отвечает за отображение количества товаров в корзине и обработку нажатия на кнопку корзины

Конструктор:
Принимает DOM-элемент шапки и обработчик открытия корзины

Поля:
`basketButton` - кнопка корзины
`counterElement` - счётчик товаров

Методы:
Сеттер `counter` - обновляет количество товаров в корзине
`render()` - возвращает DOM-элемент шапки

### Gallery — каталог товаров

Отвечает за отображение карточек товаров на главной странице

Конструктор:
Принимает DOM-элемент `.gallery`

Методы:
Сеттер `items` — принимает массив DOM-элементов карточек и отображает их в каталоге
`render()` — возвращает DOM-элемент каталога

### Card — базовый класс карточки товара

Общий родитель для трёх видов карточек: `CatalogCard`, `PreviewCard` и `BasketCard`

Отвечает за отображение общих данных товара

Поля:
`titleElement` — название товара
`priceElement` — цена товара

Методы:
Сеттер `title` - устанавливает название товара
Сеттер `price` - отображает цену товара
`render()` - возвращает DOM-элемент карточки

### CatalogCard — карточка товара в каталоге

Наследуется от `Card`

Отвечает за отображение товара в каталоге и обработку нажатия на карточку

Конструктор:
Принимает DOM-элемент карточки и обработчик нажатия

Дополнительные поля:
`categoryElement` - категория товара
`imageElement` - изображение товара

Методы:
Сеттер `category` - отображает категорию с соответствующим CSS-классом из `categoryMap`
Сеттер `image` - устанавливает изображение товара
`render()` - отображает карточку товара

### PreviewCard — подробная карточка товара

Наследуется от `Card`

Отвечает за отображение подробной информации о товаре и кнопки добавления или удаления товара из корзины.

Конструктор:
Принимает DOM-элемент карточки и обработчик нажатия на кнопку

Дополнительные поля:
`imageElement` — изображение
`categoryElement` — категория
`descriptionElement` — описание
`actionButton` — кнопка действия

Методы:
Сеттер `image` — устанавливает изображение
Сеттер `category` — устанавливает категорию
Сеттер `description` — отображает описание
Сеттеры состояния кнопки — устанавливают текст и доступность кнопки в зависимости от переданных данных. Называются buttonText и buttonDisabled
`render()` — отображает подробную карточку

### BasketCard — карточка товара в корзине

Наследуется от `Card`

Отвечает за отображение товара в корзине и обработку удаления товара

Компонент для отображения других компонентов внутри модального окна

## События приложения

### События представления

`basket:open` - пользователь нажал на кнопку корзины в шапке сайта
`card:select` - пользователь нажал на карточку товара
в каталоге (Передаётся ID выбранного товара)
`card:action` - пользователь нажал на кнопку действия
в подробной карточке товара. Передаётся ID товара
`basket:remove` - пользователь нажал кнопку удаления
товара из корзины. Передаётся ID товара
`modal:close` - пользователь нажал на крестик
или на область вне содержимого модального окна
`basket:order` - пользователь нажал на кнопку оформления заказа в корзине
`buyer:change` - пользователь изменил значениеполя формы. Передаются название поля и значение
`contacts:submit` - пользователь отправил форму с контактными данными
`order:submit` - пользователь нажал кнопку «Далее» в форме оплаты и доставки
`success:close` - пользователь нажал кнопку «За новыми покупками!» после оформления заказа
`products:changed` - изменение каталога товаров
`buyer:changed` - изменение данных покупателя. Генерируется при вызове setData() и clear()
`product:selected` - изменение выбранного товара
`basket:changed` - изменение содержимого корзины.
Генерируется при добавлении, удалении товара или очистке корзины

## Презентер

Презентер отвечает за взаимодействие моделей данных, компонентов представления и коммуникационного слоя приложения

Поскольку приложение одностраничное, презентер реализуется в файле `src/main.ts`, без создания отдельного класса

Основные задачи презентера:

Создание экземпляров моделей данных и компонентов представления
Подписка на события через `EventEmitter`
Получение каталога товаров с сервера и сохранение его в модели `Products`
Обновление интерфейса при изменении данных моделей
Открытие модальных окон с карточками товаров, корзиной и формами
Добавление и удаление товаров через модель `Basket`
Сохранение данных покупателя и обработка результатов валидации через модель `Buyer`
Отправка заказа на сервер через `LarekApi`
Отображение сообщения об успешном заказе, очистка корзины и данных покупателя

Презентер обрабатывает события, но самостоятельно их не генерирует

Перерисовка компонентов выполняется при обработке событий изменения моделей или при открытии модального окна

Действия пользователя передаются из компонентов View через брокер событий. Презентер обрабатывает их, вызывая необходимые методы моделей и компонентов представления
